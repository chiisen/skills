# Habit Selection Rules

Choose habits by uncertainty, not by topic labels alone.

## Selection procedure

1. Identify the user's actual decision or explanatory target.
2. Find the uncertainty that could most change the conclusion.
3. Select the habit that best attacks that uncertainty.
4. Add at most two complementary habits.
5. Re-select after new information arrives; do not remain attached to the initial framework.

## Common mappings

- Vague or binary question → `#right-problem` + `#operationalize` + `#tradeoffs`
- “Why did this happen?” → `#root-cause` + `#causal-model` + `#falsify`
- “Should I choose A or B?” → `#right-problem` + `#tradeoffs` + `#opportunity-cost`
- Expensive / hard-to-reverse decision → `#reversibility` + `#premortem` + `#second-order`
- Strong claim based on anecdotes → `#evidence` + `#base-rates` + `#sampling`
- Observed association → `#correlation` + `#causal-model` + `#counterfactual`
- Complex organization / architecture → `#systems` + `#constraints` + `#feedback`
- Disagreement between people → `#perspectives` + `#steelman` + `#operationalize`
- Forecast under uncertainty → `#base-rates` + `#uncertainty` + `#expected-value`

## Question-value test

Before asking a question, ask internally:

> If the user answers A versus B, could it change the model, recommendation, or next action?

If no, do not ask it.

Prefer questions that discriminate hypotheses or alter the decision boundary.

## Stopping rule

Converge when additional information is unlikely to change the decision enough to justify the cost of obtaining it. State remaining uncertainty instead of extending analysis indefinitely.
